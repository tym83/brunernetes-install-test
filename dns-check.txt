### SUMMARY (facts)
- brunernetes kube-dns (CoreDNS) ClusterIP: 10.96.0.10
- host upstream DNS (resolvectl, before install): 10.96.0.10  -> same IP => collision
- getent github.com BEFORE brunernetes install: OK works
- getent github.com AFTER install: FAIL (host DNS broken)
- root cause: kubeadm default service CIDR puts CoreDNS at 10.96.0.10, which equals the
  tenant-provided host DNS; after install kube-proxy owns 10.96.0.10, so host DNS queries
  hit CoreDNS (cluster-only) and external resolution breaks.
- note: this DNS breakage MASKS the image 403 — the pull first fails at "lookup ghcr.io ...
  server misbehaving"; only after pointing the host DNS elsewhere does the real 403 surface.
